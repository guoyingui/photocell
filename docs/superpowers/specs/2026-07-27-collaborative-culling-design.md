# PhotoCull 协同选片设计规格

> 日期：2026-07-27
> 前置：`2026-07-26-photo-culling-design.md`（单机选片）已实现完毕，
> 本规格在其之上增加**分享链接 + 多账户实时协同 + 操作留存 + 管理后台**。

---

## 0. 这次改变的是什么

原程序是一个**只监听 127.0.0.1 的本地工具**：能读任意本地路径、能复制和删除 RAW 文件，
安全模型建立在"只有坐在这台机器前的人能访问"之上。

本次需求要求把选片会话分享给客户。这意味着**服务端必须对本机以外可达**，
于是原来那条"物理接触即授权"的边界消失了。这不是加功能，是换威胁模型。
整份规格里最要紧的部分是第 9 节，其余设计都受它约束。

一句话概括新架构：

> 本地摄影师是**管理员**，身份由"请求来自回环地址"证明；
> 远端客户是**访客**，身份由"持有某条分享链接下发的用户令牌"证明；
> 访客的权限被硬性限制在"看这一个文件夹的图 + 改这一个文件夹的标记"之内，
> 访客**永远**碰不到文件系统浏览、导出、移动和管理接口。

---

## 1. 名词

| 名词 | 含义 |
|---|---|
| **库（library）** | 一个照片文件夹及其递归子目录，对应磁盘上一个 root 路径 |
| **会话（session）** | 服务端为某个 root 建立的运行时状态：资产表、元数据、markStore、烘焙任务、SSE 监听者集合。修复波之后按 root 唯一，带 `sessionId` |
| **分享（share）** | 一条链接。指向一个 root，带有效期、权限默认值、开关。一个 root 可以有多条分享 |
| **用户（user）** | 某条分享下的一个昵称账户，持有一枚用户令牌。用户属于分享，不跨分享 |
| **管理员（admin）** | 来自回环地址的请求（或持有管理令牌）。不是"一个用户"，是一种请求来源 |
| **参与者（actor）** | 一次请求背后的行为主体，取值为 `admin` 或某个 user。审计日志按 actor 记录 |

## 2. 架构

```
                     ┌─────────────────────────────────────┐
   摄影师本机         │  Express (bind: 127.0.0.1 或 LAN)   │
   127.0.0.1  ───────▶│                                     │
   = admin            │  ┌──────────── 中间件 ────────────┐ │
                      │  │ resolveActor  →  requirePerm  │ │
   客户（局域网）      │  └───────────────────────────────┘ │
   /s/<token> ───────▶│                                     │
   = user             │  ┌────┬────┬────┬────┬────┬──────┐ │
                      │  │ fs │ lib│mark│imag│expo│share │ │
                      │  │ 🔒 │    │    │    │ 🔒 │      │ │
                      │  └────┴────┴────┴────┴────┴──────┘ │
                      │  🔒 = 仅 admin                      │
                      │                                     │
                      │  会话表 Map<root, Session>          │
                      │    └─ listeners: Set<SSE>  ← 广播   │
                      └───────────────┬─────────────────────┘
                                      │
              ┌───────────────────────┼──────────────────────┐
              ▼                       ▼                      ▼
     照片文件夹/.photocull/    ~/.photocull/          （内存）
       marks.json               shares.json            presence
       thumbs/                  shares/<id>/users.json
                                shares/<id>/events.jsonl
```

**传输选型：服务端→客户端复用已有的 SSE（`/api/library/stream`），
客户端→服务端仍走普通 HTTP 写请求。不引入 WebSocket。**

理由：SSE 通道已经实现、已经有重连处理、已经跑在现有 Express 栈上；
标记变更是低频事件，客户端→服务端本来就是一次普通的幂等写。
为了这点收益引入 `ws` 和第二套协议路径不划算。

## 3. 数据存储

### 3.1 位置决策

**分享、用户、审计日志一律存在服务端级目录 `~/.photocull/`，不进照片文件夹。**

理由有三：

1. **令牌解析需要全局索引。** 访客带着 token 来的时候还没有任何库被打开，
   服务端必须先由 token 反查 root，才知道要开哪个会话。
2. **用户名和操作日志是摄影师的经营记录，不是交付物。** 照片文件夹经常整个
   打包发给客户或归档，不该把客户的账户表和行为日志夹带进去。
3. **绕开只读文件夹问题。** 照片可能在写保护的 SD 卡上；协同层的写入不该
   因此失败。（照片文件夹本身的可写性由修复波的开库写探测负责。）

```
~/.photocull/
  shares.json                    # 全部分享的索引，原子写
  shares/<shareId>/
    users.json                   # 该分享下的用户，原子写
    events.jsonl                 # 追加写的审计日志
    events.1.jsonl               # 轮转
```

`~/.photocull/` 及其内容创建时权限设为 `0700`——里面有等价于密码的令牌。

### 3.2 shares.json

```jsonc
{
  "version": 1,
  "shares": {
    "<shareId>": {
      "id": "sh_9f3a…",              // 内部 id，可出现在日志里
      "token": "…43 字符 base64url…", // 链接里的秘密，永不写进审计日志
      "root": "/Users/x/Pictures/2026-07-26 婚礼",  // 已 realpath 的绝对路径
      "label": "婚礼初选给新人",
      "createdAt": 1785000000000,
      "createdBy": "admin",
      "expiresAt": 1785600000000,    // null = 永不过期
      "revoked": false,
      "allowUserCreation": true,     // 关掉后只有已存在的用户能进
      "defaultRole": "editor",       // 新用户的初始角色
      "maxUsers": null               // null = 不限
    }
  }
}
```

### 3.3 users.json

```jsonc
{
  "version": 1,
  "users": {
    "<userId>": {
      "id": "u_2c7b…",
      "shareId": "sh_9f3a…",
      "nickname": "新娘小林",
      "nicknameKey": "新娘小林",     // 归一化后用于唯一性判断，见 §5.2
      "token": "…43 字符 base64url…", // 永不写进审计日志、永不下发给别的用户
      "role": "editor",              // "viewer" | "editor"
      "createdAt": 1785000100000,
      "lastSeenAt": 1785003400000,
      "disabled": false              // 管理员踢人：置 true，令牌立即失效
    }
  }
}
```

### 3.4 events.jsonl

每行一个 JSON 对象，**只追加，从不改写**：

```jsonc
{"ts":1785000123456,"shareId":"sh_9f3a…","actor":"u_2c7b…","nickname":"新娘小林",
 "action":"mark.set","assetId":"cam-a/IMG_0421","from":null,"to":"pick"}
```

动作全集：

| action | 载荷 | 谁产生 |
|---|---|---|
| `share.create` / `share.update` / `share.revoke` | 变更前后的字段 | admin |
| `user.join` | nickname, role | user（首次） |
| `user.resume` | — | user（带令牌回来） |
| `user.denied` | reason（`expired`/`revoked`/`full`/`creation-off`/`nickname-taken`/`bad-token`） | 未通过者 |
| `user.role-change` | from, to | admin |
| `user.disable` / `user.enable` | — | admin |
| `user.delete` | targetUserId, role | admin |
| `session.connect` / `session.disconnect` | — | user 或 admin |
| `mark.set` | assetId, from, to | user 或 admin |
| `mark.bulk` | count, to, assetIds（上限 200，超出只记数量） | user 或 admin |
| `settings.update` | 变更字段（如连拍阈值） | admin |
| `export.run` | mode, dest, counts | admin |

**令牌（share.token / user.token）在任何情况下都不得写入日志。**

轮转：单文件超过 16 MB 时改名为 `events.1.jsonl`，保留 3 代。

## 4. 标记模型与冲突

### 4.1 单一共享标记集

**所有参与者编辑同一份 `marks.json`，不做按用户分层。**

需求说的是"协同选片"——一起做出一份结果，不是各选各的再比对。
"对每个账户的操作进行记录留存"由审计日志满足，"谁标的"由归属信息满足。
按用户分层是另一个产品（客户初选 vs 摄影师终选，需要比对/合并 UI），
本需求没有要求，不做。

### 4.2 归属信息以**增量映射**形式加入，不改动既有格式

`marks.json` 现有结构 `{"marks": {"<id>": "pick" | "reject"}}` **保持不变**，
另加一张平行表：

```jsonc
{
  "version": 1,
  "marks":     { "cam-a/IMG_0421": "pick" },
  "marksMeta": { "cam-a/IMG_0421": { "by": "u_2c7b…", "at": 1785000123456 } }
}
```

这样导出链路、`derive.ts`、既有的乐观更新与回滚逻辑全都不用改读法；
`marksMeta` 缺失时 UI 退化为"不显示归属"，不报错。
读取旧格式文件（没有 `marksMeta`）直接当作空表。

### 4.3 冲突解决

- **后写覆盖，服务端时间戳为准。** 没有向量时钟、没有 CRDT——
  标记是单键单值的小状态，冲突窗口是毫秒级，代价不值得。
- 服务端写入成功后，向该会话**所有** SSE 监听者广播最终值，
  广播体带 `origin`（发起者的 actor id）和 `seq`。
- 客户端收到 `origin === 自己` 的广播直接忽略（自己已经乐观更新过了）。
- **客户端收到某个 id 的远端广播时，若本地对该 id 还有未落地的写请求，
  必须丢弃这条广播**，等自己的写请求返回后以服务端响应为准。
  否则会出现"我按了 P，别人的旧值把我的界面刷回去，我的写又成功了"的闪烁。
  现有的序号归属机制（`marks.ts` 的 pending 表）正是为此准备的，复用它。

### 4.4 权限点

- `viewer` 的任何写请求一律 **403**，服务端强制，客户端隐藏控件只是体验。
- 连拍阈值、排序等**库级设置只有 admin 能改**——它改变所有人看到的东西。
- 视图状态（当前 tab、目录筛选、展开了哪些连拍堆）是**每个客户端本地的**，
  不同步、不落盘。

### 4.5 同一个 root 上的多条分享：名单隔离，标记不隔离

同一个文件夹上挂多条链接是设计内的用法（给新人一条、给父母一条），它们共用
**同一个库会话**。于是"这个会话上有谁在线 / 谁改了什么"这两件事必须分开裁定，
因为它们的正确答案相反：

| 通道 | 是否按 shareId 过滤 | 理由 |
|---|---|---|
| `presence`（在线名单） | **过滤** | 两条链接的人之间没有任何关系，摄影师也从没把他们介绍给对方。不过滤等于把一条链接的访客昵称和 userId 直接发给另一批人 |
| `marks`（标记广播） | **不过滤** | 标记是单一共享集合（§4.1）。收到别人的改动是功能本身；不发的话两条链接的人会看到两份互相矛盾的结果 |
| `events.jsonl`（审计） | **过滤** | 同 presence：访客的写只记进他自己那条分享，管理员的写按该 root 下每条活跃分享各记一条 |

过滤的口径（`server/lib/presence.js` 的 `visibleTo`）：

- **管理员全见**——摄影师需要知道此刻一共有谁在看他的照片，不管从哪条链接进来。
- **管理员对每个人都可见**——他不属于任何一条分享，隔离对他无从谈起；
  而访客看到"摄影师在线"是这个功能的一部分。
- **访客之间 shareId 相同才可见**。认不出 viewer 的分享时落到"只看得见管理员"。

**已知代价，接受**：`marksMeta` 里的 `by` 可能指向一个不在你名单上的人。
前端已有的"已离开的成员"兜底会接住它——显示成一个叫不出名字的稳定色块
（§7.5）。也就是说"离线"和"走的是另一条链接"在客户端表现一致，
这两者本来也不该被访客区分出来。

**另一条如实记下的残留**：另一条分享有人上下线时，这一条分享的人也会收到一帧
**内容完全没变**的名单。看不出是谁，只看得出"某个时刻发生了什么"。
这条时间侧信道不在防御范围内（口径同 §9.2）。

## 5. 访客接入流程

### 5.1 链接与首屏

分享链接形如：

```
http://192.168.1.23:5173/s/<token>
```

`GET /s/<token>` 由 Express 的 SPA 兜底路由返回 `index.html`；
前端读 `location.pathname` 判定进入访客模式（见 §7.1）。

前端随即 `GET /api/share/:token/info`，服务端只返回**不敏感**的信息：

```jsonc
{ "label": "婚礼初选给新人", "assetCountHint": 1284,
  "allowUserCreation": true, "requiresNickname": true, "expiresAt": 1785600000000 }
```

链接无效时统一返回 **404** 且文案一致（`链接不存在或已失效`），
不区分"不存在"/"已过期"/"已撤销"——避免把有效 token 的存在性泄露出去。
（真实原因照常记进审计日志，管理员看得到。）

### 5.2 昵称建号

`POST /api/share/:token/join`，体 `{ "nickname": "新娘小林" }`。

- 昵称规则：去首尾空白、折叠连续空白、长度 1–24 字符（按码点计）、
  禁止控制字符。`nicknameKey` = 归一化（NFKC + 小写）后的串，用于唯一性判断。
- **判定顺序是硬要求：先查昵称是否被占用（409），再看 `allowUserCreation`（403）。**
  反过来的话，`allowUserCreation=false` 就变成了「凭昵称即可进入某人的账户」——
  任何拿到链接的人打出「新娘小林」都能继承她的全部操作历史。**昵称不是凭据。**
- **同一分享内昵称唯一。** 已被占用时返回 409 `nickname-taken`，
  文案"这个昵称已经有人在用了，换一个吧"。
  不自动加后缀——把两个人的操作显示成相近的名字会直接毁掉审计价值。
- 通过后：
  - 建 user 记录，`role = share.defaultRole`
  - 生成用户令牌，以 **httpOnly + SameSite=Lax + Path=/** 的 Cookie 下发
  - 服务端为 `share.root` 打开（或复用）库会话，返回
    `{ sessionId, user: {id, nickname, role}, share: {label},
       assetCount, warnings, skippedFiles, settings, marksRecovered }`
  - **响应里不含 `root`。** 本节原文写的是 `...openResult`，而 openResult 带着
    摄影师磁盘上的绝对路径；§5.1 明令 `info` 不返回 root，join 返回等于从后门
    说同一件事。字段要逐个挑选，不能整包展开。
- 拒绝路径（全部记 `user.denied`）：链接过期/撤销 → 404；
  `allowUserCreation === false` 且昵称不存在 → 403 `creation-off`；
  `maxUsers` 已满 → 403 `full`。

### 5.3 回访

浏览器带着 Cookie 再次访问 `/s/<token>`：
`POST /api/share/:token/resume`（无体）→ 令牌有效且用户未被禁用则直接进入，
跳过昵称表单；否则清 Cookie，回到昵称表单。

### 5.4 会话的生命周期

**一条活着的分享会把库会话钉住。** 摄影师在本地点"换文件夹"只是本地脱离，
不会把正在看图的客户踢下线。要真正结束访问，管理员撤销或让链接过期——
这与"链接可设置有效期"的语义一致：链接就是授权本身。

管理员在本地关闭一个仍有访客在线的库时，界面必须**明确告知**
"还有 N 位访客在线，链接仍然有效"，并给出直达撤销的入口。

## 6. 服务端接口

### 6.1 新增

| 方法 | 路径 | 谁可以调 | 说明 |
|---|---|---|---|
| GET | `/api/share/:token/info` | 任何人 | 只返回不敏感信息；无效一律 404 |
| POST | `/api/share/:token/join` | 任何人 | 昵称建号，下发 Cookie |
| POST | `/api/share/:token/resume` | 持 Cookie 者 | 免昵称回访 |
| POST | `/api/share/leave` | user | 主动退出，清 Cookie，记日志 |
| GET | `/api/admin/shares` | **admin** | 分享列表（含在线人数） |
| POST | `/api/admin/shares` | **admin** | 为某个 root 建分享 |
| PATCH | `/api/admin/shares/:id` | **admin** | 改有效期/开关/默认角色/标签 |
| DELETE | `/api/admin/shares/:id` | **admin** | 撤销（软删，保留日志） |
| GET | `/api/admin/shares/:id/users` | **admin** | 用户列表（**不含令牌**） |
| PATCH | `/api/admin/shares/:id/users/:uid` | **admin** | 改角色 / 禁用 / 启用 |
| DELETE | `/api/admin/shares/:id/users/:uid` | **admin** | 删除用户（令牌立即失效） |
| GET | `/api/admin/shares/:id/events` | **admin** | 审计日志，支持分页与按 actor/action 过滤 |
| GET | `/api/admin/shares/:id/events.csv` | **admin** | 导出审计日志 |

### 6.2 既有接口的权限收紧

| 路径 | 之前 | 之后 |
|---|---|---|
| `/api/fs/*`（浏览目录、mkdir） | 任何人 | **仅 admin** |
| `/api/library/open` `/close` `/prioritize` | 任何人 | **仅 admin** |
| `/api/library/settings` | 任何人 | **仅 admin** |
| `/api/export`、`/api/export/*` | 任何人 | **仅 admin** |
| `/api/library/{assets,meta,stream}` | 任何人 | admin 或 该会话对应分享下的 user |
| `/api/library/marks` GET | 任何人 | 同上 |
| `/api/library/marks` PUT | 任何人 | admin 或 `role === 'editor'` 的 user |
| `/api/thumb` `/api/original` | 任何人 | 同 GET marks |

**默认拒绝**：`resolveActor` 解析不出 actor 的请求，除白名单（静态资源、
`/api/share/:token/info`、`/api/share/:token/join`）外一律 401。

### 6.3 SSE 事件扩充

`/api/library/stream` 现有 `bake` 进度事件，新增：

```jsonc
{"type":"marks","origin":"u_2c7b…","seq":417,
 "changes":{"cam-a/IMG_0421":{"mark":"pick","by":"u_2c7b…","at":1785000123456}}}

{"type":"presence","users":[{"id":"u_2c7b…","nickname":"新娘小林","role":"editor"},
                            {"id":"admin","nickname":"摄影师","role":"admin"}]}

{"type":"role","userId":"u_2c7b…","role":"viewer"}   // 权限被改，客户端立即变灰
{"type":"kicked","reason":"disabled"}                 // 服务端随即断开该连接
{"type":"share-ended","reason":"revoked"|"expired"}   // 广播给该分享的全部访客
```

**在线状态就是 SSE 连接本身**——不做心跳。连接建立即上线，
`req.on('close')` 即下线。少一套超时判定，少一类幽灵在线。

## 7. 前端

### 7.1 三个入口，手写路由

不引入 react-router。三条路径、无嵌套、无参数解析，读 `location.pathname` 即可：

| 路径 | 界面 | 可达性 |
|---|---|---|
| `/` | 本地选片（现有全部功能 + 分享面板） | 仅 admin；非 admin 访问返回一句"请通过分享链接进入" |
| `/s/<token>` | 访客选片 | 任何人 |
| `/admin` | 管理后台 | 仅 admin |

服务端 SPA 兜底：`app.get('/*splat', …)` 返回 `index.html`
（Express 5 的通配语法是 `/*splat`，不是 `'*'`）。

### 7.2 访客界面 = 本地界面减去三块

复用 `Grid` / `StackCell` / `Thumb` / `Lightbox` / `Sidebar` **原封不动**。
去掉：文件夹选择器、导出面板、库级设置（阈值滑杆）。
加上：顶部在线成员条、只读模式下的控件置灰、被踢/链接失效的阻断层。

**`viewer` 角色的键盘快捷键必须在 `useKeyboard` 里就短路**，
不能只靠隐藏按钮——`P`/`X` 是键盘操作，没有按钮可隐藏。

### 7.3 分享面板（本地界面）

`TopBar` 加"分享"按钮 → 面板：
- 当前库已有的分享列表（标签、有效期、在线人数、链接复制按钮）
- 新建分享：标签、有效期预设（24 小时 / 7 天 / 30 天 / 永不）、
  默认角色、是否允许新用户加入
- 链接显示为完整可点 URL，并提示**这个链接就是密码，拿到的人都能进**
- 局域网地址探测：服务端返回可用的 LAN IP 列表供选择
  （多网卡时不猜，让摄影师自己挑）

### 7.4 管理后台

单页三栏：分享列表 → 该分享的用户 → 该用户/该分享的操作日志。
用户行内直接切换 只读 / 可操作，即时生效（服务端改 + SSE 推 `role`）。
日志表支持按 actor 和 action 过滤、按时间倒序、导出 CSV。

### 7.5 在线成员与归属显示

- 顶部成员条：昵称首字圆形色块，颜色由 userId 哈希得到，稳定不变。
- 缩略图角标显示最后修改者的色块（数据来自 `marksMeta`），悬停出昵称与时间。
- 不做实时光标/选区同步。多人同时看同一张图不是这个工作流的常态，
  投入产出不成比例。

## 8. 网络暴露与部署

### 8.1 默认仍然只监听回环

`npm start` 行为不变：`127.0.0.1`，不可分享。

要分享必须显式开启：

```bash
npm start -- --share
```

此时服务端绑定 `0.0.0.0`，启动时在终端打印：
- 检测到的各网卡地址
- 一条醒目的告警：**局域网内任何人只要拿到链接就能看这些照片**

### 8.2 公网不做

不内置隧道、不内置 TLS、不内置端口映射。文档明确写：
需要跨互联网就自行用 Tailscale / Cloudflare Tunnel / frp，
并且**必须**为其配置 HTTPS——否则用户令牌在明文 Cookie 里裸奔。

理由：这个服务端能读本机任意路径、能删 RAW 文件。
把它推上公网的决定应该由用户显式做出，而不是被一个默认值替他做了。

## 9. 威胁模型与安全设计

> 这一节是整份规格的约束来源。任何与它冲突的便利性设计一律让路。

### 9.1 我们防谁

| 威胁 | 处置 |
|---|---|
| **访客读摄影师的其它文件** | `/api/fs/*` 仅 admin；图片路由只接受资产 id，不接受路径（终审已实测 `?id=../../etc/passwd` → 404）；访客的会话被分享钉死在一个 root 上 |
| **访客删照片 / 触发导出** | `/api/export*` 仅 admin。**这是硬编码，不是开关。** 导出会向摄影师磁盘写入、move 模式会删除 RAW，不存在"信任的客户"这一档 |
| **访客越权改设置** | 库级设置仅 admin；`viewer` 的所有写 403 |
| **链接被转发给第三方** | 有效期 + 随时撤销 + `maxUsers` + 可关闭新用户创建；管理员能看到谁在什么时候加入 |
| **暴力猜 token** | token 为 32 字节随机（43 字符 base64url）；按 IP 限流失败的 join（60 秒内 20 次 → 429）；无效链接统一 404，不泄露存在性 |
| **CSRF**（Cookie 认证 + 状态变更请求） | Cookie 为 `SameSite=Lax`；**所有写请求必须带自定义头 `X-PhotoCull-Session`**——跨站表单提交无法设置自定义头。两道独立防线，零依赖。`?sid=` 是 **GET 专用**通道（它存在的唯一理由是 `<img src>` 和 `EventSource` 设不了请求头，而那两者都是 GET）；非 GET 请求带 `?sid=` 而没有请求头时 403 `csrf-header-required` |
| **DNS 重绑定**（攻击者页面把域名指向 `127.0.0.1`，借浏览器取得管理员身份） | 校验 `Host` 头：只接受 `localhost` / `127.x.x.x` / `[::1]` / 本机各网卡地址（`lanAddresses()`），端口须与本连接一致，其余 403 `bad-host`。这一层挂在**所有**中间件之前，对 `/api`、静态资源、SPA 兜底一视同仁。见下方 §9.3 的补充 |
| **令牌泄露进日志** | 审计日志、错误响应、终端输出一律不含 token；日志只记 `shareId` / `userId`。**唯一例外**：启动横幅里那条一次性的管理员登录 URL（见 §9.3——不打印它，`--admin-token` 就是个任何浏览器都用不了的开关） |
| **反向代理伪造回环** | admin 判定基于 TCP 源地址，**不读 `X-Forwarded-For`**；外加两条否决（见 §9.3）：配了 `--admin-token` 就只认令牌、带任何转发头的请求一律不给回环管理员身份 |

### 9.2 我们不防谁

诚实列出，避免给出虚假的安全感：

- **同一局域网内的被动嗅探。** 默认 HTTP 明文，Cookie 和照片都可被同网段抓包。
  接受这个取舍：目标场景是影棚/家里的可信网络。文档必须写清楚。
- **恶意访客的重复无效操作。** editor 可以把整库标记来回刷。
  审计日志记得下、管理员踢得掉，但不做速率限制。
- **拿到摄影师电脑物理访问权的人。** 回环即管理员。

### 9.3 admin 判定

来源判定只看 TCP 源地址，**绝不读 `X-Forwarded-For`**——那是客户端可以随便写的
请求头，读它等于把管理员权限发给任何知道加一行 header 的人：

```js
const ip = req.socket.remoteAddress;
const isLoopback = ip === '127.0.0.1' || ip === '::1' || ip === '::ffff:127.0.0.1';
```

可选 `--admin-token=<随机串>`：用于摄影师想从其他电脑管理的场景。
**不提供密码登录**——再加一套凭据管理不如复用"物理接触这台机器"。

#### 令牌怎么送进来：两条通道，其中一条是浏览器唯一走得通的

| 通道 | 谁用得上 |
|---|---|
| `X-PhotoCull-Admin: <令牌>` 请求头 | curl / Postman / 脚本，凡是能自己拼请求的客户端 |
| `pc_admin` Cookie，由 `GET /admin-login?token=<令牌>` 种下 | **浏览器**（含电脑浏览器） |

第二条不是锦上添花，是这个开关能不能用的分水岭：**浏览器没有办法给导航请求
加自定义请求头**。地址栏里敲 URL、点链接、扫二维码，发出去的都是导航请求，
`X-PhotoCull-Admin` 挂不上去。只认那个头的话，这个开关对任何浏览器都不可用——
包括本节点名的"从其他电脑管理"，也包括摄影师自己本机的浏览器（下面第 1 条否决
之后回环也不再算管理员，界面上会是满屏 403）。

`GET /admin-login?token=<令牌>` 的行为：

- 令牌定长比较通过 -> 种一枚 `pc_admin` Cookie（`HttpOnly; SameSite=Lax; Path=/`，
  不设 `Max-Age`，是会话 Cookie），然后 **302 到固定的 `/`**。
  重定向本身是设计的一部分：令牌不留在地址栏、不留下一条能后退回去的历史条目、
  不被下一跳的 `Referer` 带走。重定向目标写死为 `/`，**绝不读 `?next=` 之类的参数**
  （开放重定向，而这条路由恰好是钓鱼最想要的那种"看起来属于本站的登录链接"）。
- 令牌不对 / 没带 token / **根本没配 `--admin-token`** -> 一律 404，
  且三种情况的响应**逐字节一致**。差一个字节，这条路由就成了"这台机器有没有开
  管理员令牌"的探测器。注意开关没开时这条路由**仍然注册着**：不注册的话请求会掉进
  SPA 兜底拿到 200 + `index.html`，那本身就是一个判定器。
- 这条路径在默认拒绝的白名单里（走它的人正是还没有身份的那个浏览器）。

登录 URL 会在启动横幅里打印一次。这是 Global Constraints 那条
"令牌绝不出现在终端输出里"**唯一的例外**，理由是不打印它这个开关就没法用；
横幅同时写明这条 URL 等同于管理员密码、用完就丢。
例外只到这里为止：审计日志、错误响应，以及横幅里除这条 URL 之外的每一个字，
仍然一律不含令牌。

残余风险，诚实列出（同 §9.2 的口径）：令牌在这条 URL 里是明文走 HTTP 的，
同网段可以抓包；这条 URL 也可能进浏览器的"最近访问"建议，或者进前面那层
反向代理的访问日志。所以它是一次性的——用完关掉那个终端窗口，别截图、
别贴进聊天窗口、别存成书签。

#### 反向代理：风险方向取决于代理在哪台机器上

**这一段以前写反了**，写成了"放在反向代理后面时回环判定会失效，此时必须用
`--admin-token`"。那句话只在代理跑在**另一台机器**上时成立。反过来的情形不但
存在，而且是最常见的部署形态，后果也严重得多：

| 代理位置 | 每个转发请求的 `remoteAddress` | 后果 | 失败方向 |
|---|---|---|---|
| **另一台机器** | 代理机的局域网地址 | 没有请求是回环，管理员判定整个失效 | 关门 |
| **同一台机器**（nginx / Caddy 反代 localhost） | `127.0.0.1` | **每个访客都是管理员**：浏览整块硬盘、触发导出、move 模式删掉不可再生的 RAW | **开门** |

`--admin-token` **挡不住**同机那一种：它以前排在回环判定**之前**，是一条额外通道
而不是替代——源地址是回环就直接放行，根本走不到检查令牌那一步。

因此回环授予管理员身份这一条上加了**两条否决**（都在 `resolveActor` 里，
`isLoopback` 的判定式一个字不改）：

1. **一旦设置了 `--admin-token`，回环本身不再授予管理员身份，只有令牌算数。**
   语义是"我告诉你我前面有东西了，从现在起只认令牌"。
   （这条**必须**配合上面那条 `/admin-login` 入口一起读：否则它把这个开关变成
   一个任何浏览器都用不了的开关，摄影师连自己本机的界面都打不开。）
2. **请求带任何转发头（`X-Forwarded-For` / `X-Real-IP` / `Forwarded`）时，
   一律不授予回环管理员身份。** 按"头在不在"判断，不看值（空串也算带了）。

第 2 条的方向是安全的：攻击者只能用它把自己**降级**，没法用它提权——
直连过来的攻击者本来就不是回环，加不加头都不是管理员。注意否决加在
`resolveActor` 里，**不是**让 `isLoopback` 去读那些头：判定来源时读转发头
仍然是被禁止的。

两条否决都挡不住的残余情形：一个**不加任何转发头**转发过来的同机代理。
所以 `--share` 且未配 `--admin-token` 时，启动横幅会明确警告不要这么部署。

#### DNS 重绑定：同一个前提被伪造的另一条路

上面两条否决处理的是"回环这个前提被一层代理弄脏了"。还有一条更彻底的：
**前提本身是被伪造出来的，而且伪造它的是用户自己的浏览器。**

1. 摄影师在本机开着 PhotoCull（默认只绑 `127.0.0.1`，看起来是安全的）；
2. 他在同一个浏览器里打开 `evil.example.com` 的任意一个页面；
3. 那个域名的 DNS 记录 TTL 设成 1 秒，第二次解析时改答 `127.0.0.1`；
4. 页面里的 `fetch('http://evil.example.com:5183/api/fs/roots')` —— 浏览器
   **真的**连到了 127.0.0.1，`remoteAddress` 就是回环、也没有任何转发头，
   `resolveActor` 如实判成 **admin**；
5. 而在浏览器眼里这仍然是 `evil.example.com` 的同源请求，**响应读得到**。

后果与同机反代那一栏完全一样（浏览整块硬盘、逐张取原图、move 模式删 RAW），
失败方向同样是**开门**，而且不需要用户做任何配置——只要路过一个网页。

挡它的唯一可靠信号是 `Host` 头：浏览器发出去的是**用户地址栏里那个名字**，
不是它解析出来的 IP，而 `Host` 是 forbidden header，页面脚本改不了它。
因此加一层 `requireKnownHost`（`server/middleware/host.js`），挂在**所有**
中间件之前：

| 接受 | 拒绝（403 `bad-host`） |
|---|---|
| `localhost`（不分大小写） | 任何域名（`.local` 结尾的除外） |
| `127.0.0.0/8` 的任意地址 | 端口与本连接不一致的 |
| `::1` / `[::1]` / `[::ffff:127.0.0.1]` | 没套方括号的裸 IPv6 |
| `lanAddresses()` 列出的本机网卡地址 | 空的 `Host:` |
| `*.local`（后缀匹配，见下） | `.local` 在中间的（`x.local.evil.com`） |

两条有意为之的边界：

- **`*.local`（Bonjour / mDNS 名）放行**，这是名单里唯一一条按后缀匹配的规则。
  它不削弱这一层：`.local` 由 RFC 6762 保留给 mDNS，不走 DNS 层级，也不是根区里
  可委派的 TLD——没有人注册得到一个 `.local` 名字，而重绑定的全部前提正是
  "攻击者拿自己的权威 DNS 改答案"。残余风险只剩同一局域网内的 mDNS 抢名，
  而那种攻击者本来就能直接打 IP 绕开这个名字。
  匹配必须落在**末尾**且前面有非空标签：光一个 `.local`、以及
  `x.local.evil.com` 这种把它塞在中间的攻击者真域名，都仍然 403。
  （历史：这条一度是收紧的——客人用 `某某的-MacBook.local:5183` 会撞 403 且
  没有降级路径。2026-07-27 按上述理由翻转。）
- **没有 `Host` 头的请求放行。** HTTP/1.0 允许不带，而这一层要防的是浏览器：
  浏览器发出的每一个请求都必然带 `Host`。挡它只会误伤 curl 和健康检查。

## 10. 错误处理

| 情况 | 服务端 | 客户端表现 |
|---|---|---|
| 链接不存在/过期/撤销 | 404 统一体 | 整页阻断："链接不存在或已失效，请向摄影师索要新链接" |
| 昵称被占用 | 409 `nickname-taken` | 表单内联报错，保留已输入内容 |
| 不允许新用户 | 403 `creation-off` | "这条链接已停止接纳新成员" |
| 人数已满 | 403 `full` | "参与人数已达上限" |
| viewer 尝试写 | 403 `read-only` | Toast："你当前是只读权限" + 控件保持灰态 |
| 会话失效（换库/服务重启） | 409 `session-gone` | 提示后自动重新 join（访客持 Cookie 可静默恢复） |
| 管理员踢人 | SSE `kicked` 后断连 | 阻断层："你已被移出这次选片" |
| 链接被撤销时仍在线 | SSE `share-ended` | 同上，文案区分 |
| SSE 断线 | — | 指数退避重连（1s→30s 封顶）；**重连成功后必须全量拉一次 marks**，断线期间的增量已经丢了 |
| 磁盘写失败 | 500 `persist-failed` | 复用修复波已建立的回滚 + 明确提示路径 |

**断线重连后的全量补拉是必须的**：SSE 只推增量，
断开期间别人改的标记不会补发。不补拉就会出现两个客户端长期不一致。

## 11. 测试策略

### 11.1 必须自动化的

- **权限矩阵**：`{admin, editor, viewer, 无身份} × {每个受保护路由}` 全枚举，
  断言状态码。这张表是安全边界的唯一可执行表达，不能靠人工抽查。
- **令牌生命周期**：过期链接被拒；撤销后在线用户收到 `share-ended`；
  禁用用户的令牌立即失效；删除用户后其令牌不可用。
- **昵称唯一性**：归一化后碰撞（大小写、全角半角、前后空白）都要被 409。
- **审计日志完整性**：每个受审计动作产生且仅产生一条记录；
  **断言日志里不含任何 token 子串**（用真实令牌值做子串搜索）。
- **冲突收敛**：两个客户端并发写同一 id，服务端最终值唯一，
  两边收到的广播一致；本地有未落地写时丢弃远端广播的分支要单独测。
- **存储原子性**：`shares.json` / `users.json` 沿用既有的 临时文件→fsync→rename 写法，
  并测试写入过程中崩溃不产生半截文件。
- **日志轮转**：超限后旧文件改名、不丢行、并发追加不交错。

### 11.2 只能人工验证的（必须写进验收清单）

- 两台真机、同一局域网、同时标记同一批照片的实际体感
- 断网 30 秒再恢复，两端是否收敛到一致
- 电脑浏览器上的访客界面
- 链接在微信/邮件里被转发后仍可用（这是**功能**，也是必须让摄影师理解的**风险**）

### 11.3 承自上一阶段的诚实声明

单机部分**至今没有对着真实照片库跑过**。本阶段不会改变这一点——
协同层的自动化测试证明的是权限和收敛逻辑，
不是三千张真实 RAW 在读卡器上的表现。两份验收清单都必须真机执行过，
才谈得上交给摄影师用。

## 12. 一并解决的遗留项

终审的 **I7（扫描增量推送 / 非阻塞开库）** 归入本阶段：
协同层本来就要建一条按库的事件总线（他人标记、在线状态、角色变更），
扫描进度接在同一条总线上，比现在单独接一次、下阶段再拆掉更省。

具体：`POST /api/library/open` 立即返回 `{sessionId, phase:'scanning'}`，
扫描进度经 SSE `{"type":"scan","found":1500,"done":false}` 推送，
完成时推 `{"type":"scan","done":true}` 后客户端拉资产表。
`scan.js` 的 `onBatch` 机制早已实现并经两轮修复验证，只是从未接线。

## 13. 决策记录

| # | 决策 | 取舍 |
|---|---|---|
| D1 | 默认只监听回环，`--share` 才开放局域网 | 安全默认值优先于开箱即用 |
| D2 | 不内置公网暴露 | 这个进程能删 RAW，上公网必须是用户的显式决定 |
| D3 | admin = 回环地址，无密码 | 复用物理接触作为凭据，不新建一套账号体系 |
| D4 | SSE 而非 WebSocket | 已有实现、已有重连、事件低频；不值得引入第二套协议 |
| D5 | 单一共享标记集，不做按用户分层 | "协同"是一起做一份结果；分层是另一个产品 |
| D6 | 归属信息用平行的 `marksMeta` 表 | 导出链路和既有回滚逻辑零改动 |
| D7 | 后写覆盖，无 CRDT | 单键单值小状态，冲突窗口毫秒级 |
| D8 | 在线状态 = SSE 连接，无心跳 | 少一套超时判定，少一类幽灵在线 |
| D9 | 访客永不可导出，硬编码非开关 | 最坏后果是删掉不可再生的 RAW，不设"信任档位" |
| D10 | 昵称冲突拒绝而非加后缀 | 相似显示名会直接毁掉审计价值 |
| D11 | 无效链接一律 404 且文案一致 | 不泄露有效 token 的存在性 |
| D12 | 手写三路由，不引入 router 库 | 三条路径、无嵌套、无参数 |
| D13 | 不做实时光标同步 | 多人同看一张不是这个工作流的常态 |
| D14 | 协同数据存 `~/.photocull/`，不进照片文件夹 | 令牌解析需要全局索引；用户日志不该随交付物外发 |
| D15 | I7 并入本阶段 | 事件总线只建一次 |
